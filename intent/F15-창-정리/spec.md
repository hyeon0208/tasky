# F15 창 정리 — spec
- 작성: 2026-10-29 · 근거: intent.md(승인됨) · 상태: 승인됨(2026-10-29)

## 지금 상태 (코드로 확인)
- 전역 단축키는 `HotKey`(Clipboard.swift, Carbon `RegisterEventHotKey`, 키 하나만). 등록 결과가 `noErr`인지로 성공 판정.
- 손쉬운 사용 권한을 쓰는 코드 없음. 설정 탭 틀은 `SettingsTabs`.
- 이 Mac에 Rectangle.app이 설치돼 있다(같은 기본 단축키 → 겹침 처리가 실제로 필요).

## 우려 사항
1. **창 움직이기 — 추천: 손쉬운 사용 API(`AXUIElement`).** 맨 앞 앱(`AXFocusedApplication`) → 포커스 창 → `AXPosition`·`AXSize` 설정. Rectangle도 같은 방식. 권한 확인은 `AXIsProcessTrusted()`, 켤 때만 `AXIsProcessTrustedWithOptions(prompt: true)`.
   - 크기를 못 바꾸는 창(고정 크기 앱)은 위치만 맞추고 가운데 정렬.
   - 좌표: AX는 왼쪽 위 원점, AppKit은 왼쪽 아래 → 주 화면 높이로 뒤집는 함수 하나.
   - 영역은 `NSScreen.visibleFrame`(메뉴 막대·Dock 제외), 창이 가장 많이 걸친 화면 기준.
2. **단축키 등록 — 추천: 기존 `HotKey`를 여러 키 받도록 넓힌다(id → 동작).** 새 클래스를 만들지 않는다.
3. **겹침 확인 — 추천: 세 가지.**
   - a) **등록 실패**: 다른 앱이 이미 Carbon으로 같은 키를 등록했으면 `RegisterEventHotKey`가 실패(`eventHotKeyExistsErr`) → '겹침(다른 앱)'.
   - b) **macOS 시스템 단축키**: `com.apple.symbolichotkeys`의 켜진 항목(키코드·수정키)과 비교 → '겹침(시스템)'. 예: ⌃←/→(Space 이동)는 ⌃⌥와 다르므로 기본값과는 안 겹친다(추정, 읽어서 확인).
   - c) **창 정리 앱 실행 중**: Rectangle·Magnet·Spectacle·Moom·Loop 번들 ID가 실행 중이면 켤 때 "같은 단축키를 쓰는 앱이 켜져 있어요" 한 줄(앱 이름은 쓰되 안내·홍보는 하지 않음). 실제 겹침은 a)로 판정된다(그 앱들이 먼저 등록하므로).
   - 겹친 단축키는 등록하지 않고 설정에서 빨간 '겹침'으로 보이고, 키 녹화로 다른 키를 고르게 한다.
4. **동작 목록 — intent 기본값 그대로 18개:** 반쪽 4, 최대화, 가운데, 원래대로, 4분의 1 4, 3분의 1 3, 3분의 2 2, 다른 모니터 2. 같은 반쪽을 반복 누르면 Rectangle처럼 1/2→2/3→1/3 순환(추정: Rectangle 기본 동작, 이번엔 포함).
5. **원래대로 — 추천: 창마다 맞추기 직전 위치를 기억(`pid + 창 제목` 키, 메모리만).** 앱을 끄면 잊는다.
6. **끌어서 맞추기 — 추천: `NSEvent.addGlobalMonitorForEvents(.leftMouseDragged/.leftMouseUp)`로 마우스만 듣기.**
   - 드래그 시작 때 커서 아래 창(`AXUIElementCopyElementAtPosition`)이 실제로 움직였을 때만 창 끌기로 본다(글자 선택 드래그 무시).
   - 화면 가장자리 5pt 안: 왼/오 = 반쪽, 위 = 최대화, 네 모서리 = 4분의 1. 들어가면 반투명 미리보기 패널(`FloatingPanel`, 클릭 통과), 놓으면 맞춤, 벗어나면 미리보기 닫힘.
   - 키 입력은 듣지 않는다.
7. **설정 — 추천: 새 '창 정리' 탭(아이콘 rectangle.split.2x1).** 켜기(기본 꺼짐), 권한 상태 + '권한 열기', 끌어서 맞추기 켜기, 동작별 단축키 줄(키 녹화·겹침 표시·지우기). 원형 메뉴 칸은 이번엔 넣지 않는다(18개라 링에 맞지 않음).
8. **라이선스 — Rectangle은 MIT.** 코드를 옮기지 않고 같은 방식으로 새로 쓴다. 비율 순환 같은 동작을 참고한 곳엔 주석으로 출처를 남긴다.

## 요구사항
- R1. 켜고 권한이 있으면 단축키로 맨 앞 창을 정해진 영역으로 맞춘다. 권한이 없으면 이 기능만 꺼진 채 '권한 열기'.
- R2. 원래대로로 맞추기 전 위치·크기로 돌아간다.
- R3. 가장자리·모서리로 끌면 미리보기 후 맞춤.
- R4. 겹치는 단축키는 등록하지 않고 '겹침'으로 보인다. 키는 바꿀 수 있다.
- R5. 끄면 모든 단축키 등록·마우스 감시를 해제한다.

## 설계
- `WindowSnap.swift`(새로): `SnapAction`(18개, 이름·기본 키), `SnapMath`(순수: 화면 영역 + 동작 → 사각형, 순환, 가장자리 판정), `AXWindow`(앞 창 읽기·쓰기·좌표 변환), `SnapController`(켜기/끄기·권한·기억·드래그 감시·미리보기), `Conflicts`(시스템 단축키 읽기·창 정리 앱 확인).
- `Clipboard.swift`의 `HotKey`: 여러 등록을 받도록 넓힘(클립보드 동작은 그대로).
- `PetController`: 설정 탭 추가, 시작 때 켜져 있으면 `SnapController.start()`.

## 검증 방법
- 자체 검사(`SnapMath`): 1440×900 영역에서 왼쪽 반 = (0,0,720,900), 4분의 1·3분의 1·3분의 2 사각형, 반쪽 반복 순환, 가장자리 판정(5pt 안/밖, 모서리 우선), AX↔AppKit 좌표 왕복(두 모니터 배치).
- 시스템 단축키 읽기가 지금 Mac에서 파싱되는지.
- 실제 창 이동·권한·드래그 미리보기·Rectangle과의 겹침은 사용자 확인.
