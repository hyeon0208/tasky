## 작업 순서와 각 단계의 검사

### 1. `Briefing` — 모으기 로직 (순수)
- 상태: `awaySince: Date?`, `items: [Item]`. 항목 종류: 작업(세션 스냅샷), 변환(끝난 시각, 결과 파일들).
- `leave(at:)`: `awaySince`가 비어 있을 때만 기록(겹친 자리 비움은 처음 시각 유지).
- `collect(sessions:conversions:)`: `awaySince`가 없으면 아무것도 안 함(잠금 해제와 깨어나기가 연달아 와도 한 번만). 있으면
  - 지금 승인 대기인 세션 전부(떠나기 전부터 기다린 것 포함),
  - `awaySince` 이후 바뀐 실패·끝남 세션,
  - `awaySince` 이후 끝난 변환
  을 모아 기존 항목과 합친다(같은 세션은 최신 상태 하나). 정렬: 승인 대기 → 실패 → 끝남 → 변환, 같은 묶음 안에서는 최근 것 먼저. `awaySince`를 비우고, 새로 더한 개수를 돌려준다.
- `clear()`: 항목을 비운다.
- **검사:** 자체 검사에 ① 비움 이전 끝남 제외·이후 포함 ② 이전부터 기다린 승인 대기 포함 ③ 순서 ④ 같은 세션 중복 없음 ⑤ 겹친 `leave`는 처음 시각 유지 ⑥ `awaySince` 없이 `collect` → 0건 ⑦ `clear` 후 비어 있음.

### 2. 펫마다 브리핑과 변환 기록 (`PetController`)
- 펫마다 `briefing`과 `conversions: [(Date, [URL])]`(최근 50개). 변환이 끝나면 기록.
- `leave()`, `collect(sessions:)`: 그 펫의 `accepts(tool)`에 맞는 세션만 넘긴다. 새로 더한 게 있으면 손 흔들기.
- 첫 칸 우선순위: 그 사이 N건 > 기다리는 작업 > 끝난 작업 > 변환 결과 > 쓰다듬기.
- **검사:** 자체 검사에 "도구 설정에 맞지 않는 세션 제외"(필터 함수를 순수하게 분리해 검사).

### 3. 감지 (`App`)
- `DistributedNotificationCenter`: `com.apple.screenIsLocked` → 모든 펫 `leave`, `com.apple.screenIsUnlocked` → 모든 펫 `collect`.
- `NSWorkspace.shared.notificationCenter`: `willSleepNotification` → `leave`, `didWakeNotification` → `collect`.
- 싱잉볼: 쉼 시작(`openBowl`) → `leave`, 쉼 끝(`endRest`) → `collect`. F6의 `listPet()?.openAgentList()` 임시 코드와 `shortcut:` 주석은 삭제.
- **검사:** 빌드. 실제 잠금·잠자기는 사용자 확인.

### 4. 손 흔들기 (`PetView`)
- 몸 옆(눈 반대쪽 아닌 앞쪽 위)에 작은 둥근 손을 그리는 층(`CAShapeLayer`)을 두고, `waveHand()`가 보이게 한 뒤 약 1.5초 동안 좌우로 세 번 흔들고 숨긴다. 동작 줄이기면 흔들지 않고 1.5초 보였다 사라진다.
- 펫 크기·색·좌우 반전(가장자리 빼꼼)에 맞춰 위치를 계산한다.
- **검사:** 빌드. 모양은 사용자 확인.

### 5. 브리핑 창 (`BriefingWindow`)
- 작업 알림 목록과 같은 모양의 펫 옆 패널(약 420×380). 묶음 제목(승인을 기다리는 작업·실패한 작업·끝난 작업·변환 결과)과 항목.
- 작업 항목: 도구 아이콘·이름·상태·마지막 응답 앞 3줄(끝남), '터미널로 가기'. 변환 항목: 파일 이름들, 'Finder에서 보기'.
- 닫기 버튼·Esc·바깥 클릭으로 닫힘. 닫히면 그 펫의 `briefing.clear()`.
- **검사:** 빌드. 모양은 사용자 확인.

## 무엇이 깨질 수 있나 (위험)
| 위험 | 대응 |
|---|---|
| 잠금과 잠자기가 겹쳐 브리핑이 두 번 쌓임 | `leave`는 처음 시각 유지, `collect`는 `awaySince`가 있을 때 한 번만 |
| 승인 대기를 매번 넣기로 해서 같은 항목이 반복 | 사용자 결정(우려 2). 같은 세션은 하나로 합쳐 중복만 막는다 |
| 쉼 중 알림 보류(F6)와 브리핑이 다르게 동작 | 쉼 종료 시 브리핑이 쉼 시작 이후를 모두 모으므로 F6 보류 목록은 표시에 쓰지 않는다(알림 억제에만 사용) |
| 비공식 잠금 알림이 오지 않음 | 잠금 후 브리핑만 빠짐(spec 결정). 잠자기·쉼은 영향 없음 |
| 브리핑 창의 세션이 그사이 끝나 사라짐(SessionEnd) | 모을 때의 스냅샷을 보여 준다 |

**가장 위험한 단계:** 3번(감지). 실제 잠금·잠자기 알림은 제가 일으킬 수 없어 화면 확인이 필요하다. 1번 로직을 자체 검사로 단단히 해 둔다.

## 구현 결과와 계획 대비 차이 (2026-10-22)
- 변환 항목은 파일 이름 전부가 아니라 "첫 파일 외 N개"로 보인다.
- 브리핑 창은 열 때 키 창이 된다(Esc를 바로 받도록). 원형 메뉴에서 사용자가 연 경우라 이미 포커스가 펫 쪽에 있다. 작업 알림 목록은 키 창이 되지 않아 두 창이 조금 다르다.
- 자리 비움은 출처(화면 잠금·잠자기·쉼)를 함께 세어(`AwayState`), 모두 끝났을 때만 모은다(독립 검토 A·B 반영, 계획에 없던 구조).
- 창을 닫으면 브리핑 전체가 아니라 창에 보여 준 항목만 비운다(독립 검토 C 반영).
- F6 `RestSession.held`는 이제 표시에 쓰이지 않고 알림 억제 판단만 한다(남은 데이터, 정리는 보류).

## 독립 검토 반영 (새 문맥 서브에이전트)
- 고침 A: 쉼 중 잠금·해제가 있으면 쉼 끝의 브리핑이 사라지던 문제 → 출처를 함께 세어 쉼이 끝날 때 모음.
- 고침 B: 뚜껑을 닫으면(잠금→잠자기→깨어나기→잠금 해제) 잠긴 화면에서 브리핑이 소비되던 문제 → 잠금 해제에서 모음.
- 고침 C: 브리핑 창이 열린 사이 새로 모인 항목이 닫을 때 같이 지워지던 문제 → 보여 준 항목만 지움.
- 고침 D: 펫을 보내거나 숨겨도 브리핑 창이 남던 문제 → 함께 닫음.
- 고침 E: 브리핑 창이 열린 상태에서 칸을 누르면 원형 메뉴가 남던 문제 → 먼저 닫음.
- 자체 검사 추가: 같은 세션의 묶음 이동, 보여 준 항목만 비움, 그 사이 일이 없으면 0건, 자리 비움 출처 3가지 순서.
- 남김(사용자 결정): 승인 대기는 돌아올 때마다 다시 들어간다(우려 2). 브리핑 속 항목은 모을 때의 모습(스냅샷)이다.
