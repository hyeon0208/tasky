## 작업 순서와 각 단계의 검사

### 1. `RestSession` — 시간과 보류 규칙 (순수 로직)
- 시작 시각·길이(60·180·300·600초)로 남은 시간 계산, 끝났는지 판단.
- `shouldHold(state)`: 끝남·실패 → 보류, 승인 대기 → 보류하지 않음(작게 표시), 일하는 중 → 알림 없음.
- 보류 목록(세션 ID 중복 없이)과 승인 대기 개수.
- **검사:** 자체 검사에 남은 시간(시작 직후·중간·끝 이후), 보류 규칙 4가지 상태, 같은 세션 두 번 → 한 번만 보류.

### 2. `BowlSynth` — 소리 합성
- `AVAudioEngine` + `AVAudioSourceNode`. 기본음 220Hz와 배음(×2.7, ×5.1, ×8.2), 배음마다 +0.7~1.5Hz 어긋난 쌍으로 맥놀이.
- `strike()`: 진폭을 1로 올리고 약 6초 지수 감쇠.
- `rub(angularSpeed:)`: 그릇 중심 기준 각속도(rad/s) → 목표 진폭. 느리면 0, 1~6 rad/s에서 오르고, 그보다 빠르면 오히려 줄어든다(실제 싱잉볼처럼 일정한 속도일 때 크게).
- 진폭은 매 오디오 블록에서 목표값으로 천천히 따라간다(끊김 방지). 렌더 스레드는 미리 잡은 값만 읽고 메모리를 새로 잡지 않는다.
- `start()`·`stop()`: 쉼 시작·끝에만 엔진을 켜고 끈다.
- **검사:** 자체 검사에 `targetLevel(angularSpeed:)`(0일 때 0, 적당한 속도에서 최대, 너무 빠르면 감소), 감쇠 계산, 엔진 시작 후 `isRunning == true`, `stop()` 후 `false`(검사 중에는 출력 볼륨 0).

### 3. `BowlWindow` — 펫 옆 창
- 약 240×300 `FloatingPanel`(클릭하면 키 창, 바깥 클릭으로 닫히지 않음). 펫이 화면 오른쪽이면 왼쪽에 붙는다.
- 시작 전: 그릇 그림 + 1·3·5·10분 버튼. 고르면 바로 시작.
- 쉬는 중: 그릇(클릭 = 치기, 창 안에서 원 그리기 = 문지르기), 남은 시간(1초마다 갱신), '그만두기', 아래 한 줄 "승인을 기다리는 작업 N"(0이면 숨김, 누르면 작업 알림 목록).
- Esc = 그만두기. 끝나면 세 번 울리고 약 2초 뒤 닫힘.
- 커서 위치는 이 창 안에서만 읽는다(전역 감지 없음).
- **검사:** 빌드. 화면 모습·조작감은 사용자 확인.

### 4. 쉼 상태와 알림 보류 (`App`, `PetController`)
- `App.rest: RestSession?`(전역). '싱잉볼' 칸 → `App.startRest(from: pet)`. 이미 쉬는 중이면 그 창을 앞으로.
- `agents.onChange`: 쉬는 중이면 세션 상태·콩알은 평소대로 갱신하되, `shouldHold`이면 알림 창·알림음 대신 보류 목록에 넣고, 승인 대기는 창의 한 줄만 갱신.
- 쉼 끝(시간 종료·그만두기·Esc): 엔진 정지, 호흡 정지, 창 닫기, 보류 목록이 있으면 쉼을 시작한 펫에서 작업 알림 목록을 연다(F8 전까지의 임시 방식, 코드에 `shortcut:` 주석으로 표시).
- `openAgentList()`를 `App`에서 부를 수 있게 공개 범위만 넓힌다.
- **검사:** 자체 검사에 "쉬는 중 끝남 이벤트 → 알림 창 호출 없음, 보류 1건", "쉬는 중 승인 대기 → 보류 0건, 대기 1건".

### 5. 호흡과 그릇 (`PetView`)
- `breathing = true`면 레이어에 10초 주기 키프레임(0~4초 1.0→1.08, 4~10초 1.08→1.0) 반복. 크기 기준점을 가운데로 맞춘다.
- 동작 줄이기 설정이면 크기 대신 밝기(투명도 1.0↔0.8)만.
- `holdingBowl = true`면 몸 아래쪽에 작은 그릇을 겹쳐 그린다.
- 기존 쓰다듬기 애니메이션과 키를 나눠 서로 덮어쓰지 않게 한다.
- **검사:** 빌드. 실제 움직임은 사용자 확인.

- 앱을 다시 띄우기 전에 사용자에게 확인한다(실행 중인 펫이 꺼짐).
- 새 문맥에서 독립 검토(서브에이전트)하고, 이 plan과 달라진 점을 보고한다.

## 무엇이 깨질 수 있나 (위험)
| 위험 | 대응 |
|---|---|
| 오디오 렌더 스레드에서 끊김·잡음 | 렌더 블록은 미리 잡은 버퍼와 값만 사용, 진폭은 블록마다 서서히 따라감 |
| 쉼 중 알림 보류 로직이 평소 알림까지 막음 | 보류 판단을 `rest != nil`일 때만, 쉼 끝에 반드시 `rest = nil`. 자체 검사로 쉼 밖 알림이 그대로인지 확인 |
| 호흡 애니메이션의 크기 기준점 변경으로 펫이 미세하게 움직임 | 기준점 변경 시 위치를 함께 보정, 쉼 끝에 원래대로 복원 |
| 펫을 보내거나(삭제) 숨긴 상태에서 쉼이 끝남 | 쉼을 시작한 펫이 없으면 첫 번째 보이는 펫에서 목록을 연다 |
| 앱 종료 시 엔진이 남음 | 쉼 끝·앱 종료 모두 `stop()` 호출 |

**가장 위험한 단계:** 4번(알림 보류). 기존 F4 알림 흐름을 건드리므로 자체 검사로 쉼 안·밖을 모두 확인한다.

## 구현 결과와 계획 대비 차이 (2026-10-22)
- 창 크기 240×320(계획 약 240×300).
- 문지르기 세기: 0.5 rad/s 미만 0, 3 rad/s에서 최대, 9 rad/s까지 줄어 0.3 유지(계획: 1~6 rad/s에서 오름). 그릇 테두리 근처(반지름 55~110%)에서만 문지르기로 인정.
- 맥놀이 간격 0.9~1.6Hz(계획 0.7~1.5Hz).
- 진폭은 블록마다가 아니라 표본마다 목표를 따라감(더 매끄러움).
- 크기 기준점을 바꾸지 않고 가운데 기준 변환으로 호흡(위치 보정이 필요 없음).
- 쉼 시작은 '창 열기 → 시간 고르기' 두 단계. 시작 전에는 '닫기' 버튼.
- 오디오 엔진은 끝 울림(세 번) 후 약 3초 뒤 0.15초 동안 줄여서 끈다(쉼 끝 직후 바로 끄지 않음). 새 쉼이 그 사이 시작되면 끄지 않는다.
- 알림 결정 로직을 `RestSession.shouldAnnounce`로 분리해 App과 자체 검사가 같은 함수를 쓴다.
